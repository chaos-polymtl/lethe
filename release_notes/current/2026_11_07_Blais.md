## [Master] - 2026/11/07

### Fixed

- MINOR When the output was controlled by an `output time frequency` (`set output control = time`), the initial condition and the last iteration of the simulation were never written. The next output time was also measured from the time of the previous output instead of being a multiple of the output time frequency, so the output times drifted when the time step was not a divisor of the output time frequency, and output times such as the end time could be skipped. Furthermore, since the previous output time was updated whenever the output criterion was queried, a second query within the same iteration always returned false. As a consequence, the solvers that query it more than once per iteration did not write all their outputs (e.g., the fluid results of the CFD-DEM solvers were never written, and neither were the Lagrangian post-processing results of the DEM solver). Lastly, a restarted simulation always wrote an output at its first iteration. The output times are now the multiples of the output time frequency starting from the lower bound of the `output time interval`, and an iteration is an output iteration if its time step reaches or crosses one of these output times. The initial and last iterations are always written when they lie within the `output time interval`. The specific `output times` suffered from similar issues, since they were processed one at a time with a counter that was advanced when the output criterion was queried: a second query within the same iteration missed the output written after an output time, and the counter got stuck, so that all the following output times were never written, when an output time was equal to the initial time, when several output times lay within the same time step, or when the output times were not sorted. An iteration is now an output iteration if the time step that leads to it, or the next time step, reaches or crosses any of the output times, which may be given in any order. The checkpoint files no longer store the index of the next output time; this line is ignored when restarting from older checkpoint files. Only the output files are affected, not the simulation results. [#2201](https://github.com/chaos-polymtl/lethe/pull/2201)
