## [Master] - 2026/08/17

### Added

- MAJOR The DEM (`lethe-particles`) and ray tracing (`lethe-particles-ray-tracing`) solvers now read their triangulation through the same routine as the CFD solvers, `read_mesh_and_manifolds`. Both solvers consequently gain the `manifolds` subsection and the `boundaries refined`/`initial boundary refinement` parameters of the `mesh` subsection; the latter two were already parsed by these solvers but were silently ignored. `lethe-particles` additionally gains the `box refinement` subsection, which refines the background mesh within user-specified boxes before the particles are inserted. [#PR](link)
- MAJOR The `box refinement` subsection now accepts the `lethe` built-in grids. The mesh reading it used was implemented inline in `NavierStokesBase::box_refine_mesh` and only supported the `dealii` and `gmsh` types; it now delegates to `attach_grid_to_triangulation`, which supports every mesh type. [#PR](link)

### Changed

- MAJOR The refinement requested by `enable target size` in the `mesh` subsection is now skipped when a simulation is restarted from a checkpoint, which is what `initial refinement` and `initial boundary refinement` already did. Previously, the CFD solvers refined the mesh towards the target size even on restart, and the triangulation subsequently loaded from the checkpoint was refined a second time. No parameter file in the repository uses `enable target size`, so no existing result is affected. [#PR](link)
- MINOR `Parameters::get_size_of_subsections` and `get_max_subsection_size` take a new `require_subsection_size` argument. It defaults to `true`, which preserves the requirement that a parameter file declare the size of at least one variable size subsection. The DEM solvers pass `false`, since their boundary conditions are declared in a `DEM boundary conditions` subsection with a `number of boundary conditions` entry rather than in a `boundary conditions` subsection: a DEM parameter file that declares no manifold now yields subsections of size zero instead of raising an exception. This is what allows the `manifolds` subsection to be declared by `lethe-particles`. [#PR](link)
- MINOR The CFD and DEM boundary conditions now describe periodicity with a single `Parameters::PeriodicBoundaries` map, keyed by the principal periodic boundary id and holding the neighbor boundary id and the direction of periodicity of each pair. It replaces the two parallel maps each solver family carried, which had to be kept in sync and were checked against each other at run time. Parameter files are unaffected: the `periodic id`/`periodic direction` entries are parsed exactly as before. [#PR](link)

### Removed

- MINOR The DEM-specific mesh reading, `source/dem/read_mesh.cc` and `include/dem/read_mesh.h`, was a partial re-implementation of the CFD routine and was removed along with its independent implementation of the triangulation periodicity setup. Both solver families now share `read_mesh_and_manifolds` and `setup_periodic_boundary_conditions`. [#PR](link)

### Fixed

- MINOR The background triangulation of DEM and ray tracing simulations is now built with the `limit_level_difference_at_vertices` mesh smoothing flag, as the CFD triangulations already were. Without it, the locally refined meshes produced by the newly available boundary and box refinements could have a level difference greater than one across a vertex. [#PR](link)
- MINOR Setting `simplex = true` in a DEM or ray tracing simulation now raises an explicit error instead of reaching an unimplemented deal.II code path. Simplex meshes require a `parallel::fullydistributed::Triangulation`, whereas the particle-wall contact search, the load balancing and the checkpointing of these solvers all require a `parallel::distributed::Triangulation`. [#PR](link)
- MAJOR The `initial translation` and `initial rotation angle`/`initial rotation axis` of a `dealii` mesh read with `simplex = true` are now applied. Only the `scale` factor was, so a simplex mesh silently stayed at the location described by its `grid arguments`. The transformation is applied to the quad/hex mesh before it is refined and converted to simplices, which is where the scaling was already applied. No parameter file of the repository translates or rotates a `dealii` simplex mesh, so no existing result is affected. [#PR](link)
- MINOR Two bugs in the mesh reading that `NavierStokesBase::box_refine_mesh` implemented inline were fixed by delegating to `attach_grid_to_triangulation`: the box mesh of a `gmsh` + `simplex` refinement box overwrote the main triangulation instead of the box triangulation, and the `initial refinement` of a `dealii` + `simplex` refinement box was applied twice. Only simplex refinement boxes were affected, and no parameter file of the repository uses one, so no existing result is affected. [#PR](link)
- MINOR The cell flagging loop of the box refinement, moved to `LetheGridTools::flag_cells_in_refinement_box`, now only sets refinement flags on locally owned cells, as the rest of the code base does. This does not change any result, since a distributed triangulation takes the refinement of a ghost cell from its owner, which flags it independently. [#PR](link)
- MINOR The warning raised when a mesh `scale` factor is applied to a `dealii` or `lethe` grid is now only raised when the grid actually carries a curved manifold, which is the case in which the scaling can distort the geometry. Grids described solely by the flat manifold, such as the `hyper_cube` and `hyper_rectangle` grids commonly used to delimit a refinement box, no longer trigger it. The warning is also printed by a single process in every case; the triangulation of a refinement box being serial, its communicator is `MPI_COMM_SELF` and every process considered itself to be the root one. [#PR](link)
- MINOR `Parameters::Manifolds::size`, `Parameters::Manifolds::max_size` and the members of `Parameters::SizeOfSubsections` were left uninitialized when default constructed. They are now zero-initialized, which also fixes `navier_stokes_parameter_template` declaring a garbage number of manifold subsections. [#PR](link)

### Documentation

- MINOR The `mesh` section of the DEM documentation was rewritten: it previously stated that the DEM and CFD sections were "almost identical", which is now literally true. It documents the newly available `manifolds` and `box refinement` subsections and the lack of support for simplex meshes. The restart behavior of `enable target size` was documented in the CFD `mesh` section. [#PR](link)
