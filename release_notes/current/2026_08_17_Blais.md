## [Master] - 2026/08/17

### Added

- MAJOR The DEM (`lethe-particles`) and ray tracing (`lethe-particles-ray-tracing`) solvers now read their triangulation through the same routine as the CFD solvers, `read_mesh_and_manifolds`. DEM simulations consequently gain three features that were previously restricted to the CFD solvers: the `manifolds` subsection, the `box refinement` subsection, and the `initial boundary refinement`/`boundaries refined` parameters of the `mesh` subsection. The latter two were already parsed by `lethe-particles` but were silently ignored. The DEM-specific `source/dem/read_mesh.cc`, a partial re-implementation of the CFD routine, was removed, and the two independent implementations of the triangulation periodicity setup were merged into one. [#PR](link)

### Changed

- MAJOR The refinement requested by `enable target size` in the `mesh` subsection is now skipped when a simulation is restarted from a checkpoint, which is what `initial refinement` and `initial boundary refinement` already did. Previously, the CFD solvers refined the mesh towards the target size even on restart, and the triangulation subsequently loaded from the checkpoint was refined a second time. No parameter file in the repository used `enable target size`, so no existing result is affected. [#PR](link)

### Fixed

- MINOR The background triangulation of DEM and ray tracing simulations is now built with the `limit_level_difference_at_vertices` mesh smoothing flag, as the CFD triangulations already were. Without it, the locally refined meshes produced by the newly available boundary and box refinements could have a level difference greater than one across a vertex. [#PR](link)
- MINOR Setting `simplex = true` in a DEM or ray tracing simulation now raises an explicit error instead of reaching an unimplemented deal.II code path. Simplex meshes require a `parallel::fullydistributed::Triangulation`, whereas the particle-wall contact search, the load balancing and the checkpointing of these solvers all require a `parallel::distributed::Triangulation`. [#PR](link)
- MINOR `Parameters::Manifolds::size` and `Parameters::SizeOfSubsections` were left uninitialized when default constructed. They are now zero-initialized, which also fixes `navier_stokes_parameter_template` declaring a garbage number of manifold subsections. [#PR](link)
- MAJOR The `initial translation` and `initial rotation angle`/`initial rotation axis` of a `dealii` mesh read with `simplex = true` are now applied. Only the `scale` factor was, so a simplex mesh silently stayed at the location described by its `grid arguments`. The transformation is applied to the quad/hex mesh before it is refined and converted to simplices, which is where the scaling was already applied. No parameter file of the repository translates or rotates a `dealii` simplex mesh, so no existing result is affected. [#PR](link)
- MINOR The warning raised when a mesh `scale` factor is applied to a `dealii` or `lethe` grid is now only raised when the grid actually carries a curved manifold, which is the case in which the scaling can distort the geometry. Grids described solely by the flat manifold, such as the `hyper_cube` and `hyper_rectangle` grids commonly used to delimit a refinement box, no longer trigger it. The warning is also printed by a single process in every case; the triangulation of a refinement box being serial, its communicator is `MPI_COMM_SELF` and every process considered itself to be the root one. [#PR](link)
- MINOR `NavierStokesBase::box_refine_mesh` re-implemented mesh reading inline instead of using `attach_grid_to_triangulation`. It now delegates to the shared routine, which fixes two bugs: the box mesh of a `gmsh` + `simplex` refinement box overwrote the main triangulation instead of the box triangulation, and the `initial refinement` of a refinement box was applied twice. Box refinement also now accepts the `lethe` built-in grids, which the inline implementation did not support. The cell flagging loop, moved to `LetheGridTools::flag_cells_in_refinement_box`, now only sets refinement flags on locally owned cells, as the rest of the code base does. This does not change any result, since a distributed triangulation takes the refinement of a ghost cell from its owner, which flags it independently. [#PR](link)

### Documentation

- MINOR The `mesh` section of the DEM documentation was rewritten: it previously stated that the DEM and CFD sections were "almost identical", which is now literally true. It documents the newly available `manifolds` and `box refinement` subsections and the lack of support for simplex meshes. The restart behavior of `enable target size` was documented in the CFD `mesh` section. [#PR](link)
