## [Master] - 2026/09/27

### Changed

- MINOR The enum parameters whose accepted strings are identical to the enumerator names (e.g. `bdf1`, `gls`, `amg`) are now converted with magic_enum, in both directions, through two new helpers in `core/utilities.h`: `enum_to_string()` derives the default-value string in `declare_parameters()` and `string_to_enum()` parses the value in `parse_parameters()`. This removes 45 handwritten `to_string()` switch functions and the matching string comparison chains from `parameters.cc`, `parameters_cfd_dem.cc`, `parameters_lagrangian.cc`, `parameters_multiphysics.cc` and `initial_conditions.cc`. The string comparison chains of the manifold `type` (`manifolds.cc`) and of the solid object `thermal boundary type` (`solid_objects_parameters.h`) are replaced in the same way. The handwritten conversions are kept for the parameters whose strings differ from the enumerator names (e.g. `extra verbose`, `power-law`, `fluid 0`) or that accept aliases (e.g. the rolling resistance torque method). Lethe now requires deal.II to be configured with magic_enum (`DEAL_II_WITH_MAGIC_ENUM`, bundled since deal.II 9.8), which is checked at configure time. No parameter, accepted value or output is changed; only the message of the (unreachable in practice) error raised for a value that matches the parameter pattern but not an enumerator is now generic.
