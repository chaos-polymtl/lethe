## [Master] - 2026/11/16

### Changed

- MINOR The boundary condition types are no longer stored in a single `BoundaryConditions::BoundaryType` enumeration shared by all physics. Each physics now has its own enumeration (`FluidDynamicsBoundaryType`, `HeatTransferBoundaryType`, `TracerBoundaryType`, `CLSBoundaryType`, `CahnHilliardBoundaryType`, `TimeHarmonicMaxwellBoundaryType` and `QMOMBoundaryType`), which only contains the boundary condition types supported by this physics, and the `BoundaryConditions` base class is templated on it. Comparing the boundary type of one physics with a value of another physics is now a compilation error. The `type` parameter of the tracer, QMOM, CLS and Cahn-Hilliard boundary conditions is now declared with `declare_enum_entry()` and parsed with `string_to_enum()`, like the fluid dynamics, heat transfer and time-harmonic Maxwell ones, instead of a handwritten `Patterns::Selection` and string comparisons. Their accepted values and default values are unchanged. The `beta` and `boundary_layer_thickness` members move from the base class to `FluidDynamicsBoundaryConditions`, their only user. [#PR](https://github.com/chaos-polymtl/lethe/pull/PR)

### Fixed

- MINOR The PDE-based interface reinitialization of the CLS took its periodic constraints from the fluid dynamics boundary conditions instead of the CLS boundary conditions, unlike the CLS solver and its other subequations. It now uses the CLS boundary conditions. Results only change when the fluid dynamics and CLS periodic boundary conditions differ. [#PR](https://github.com/chaos-polymtl/lethe/pull/PR)
