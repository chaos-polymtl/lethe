## [Master] - 2026/07/24

### Fixed

- MAJOR Fixed a bug that corrupted the void fraction history stored in the checkpoint of `lethe-fluid-particles-matrix-free` simulations that use dynamic load balancing together with the void fraction time derivative, preventing them from restarting consistently. In `load_balance`, the fluid solution vectors have their ghost values refreshed after the `SolutionTransfer` interpolation onto the repartitioned mesh, but the void fraction vectors (`void_fraction_solution` and `void_fraction_previous_solution`) did not. `interpolate` only fills locally owned entries, so the void fraction vectors were left with stale ghost values. When a checkpoint was written on a load balance step, these stale ghosts were first propagated by `percolate_void_fraction` (which copies whole vectors) and then packed into the checkpoint by `prepare_for_serialization`, which reads ghost values to serialize the dofs of locally owned cells that sit on a subdomain boundary. The checkpoint therefore stored incorrect void fractions on those dofs, most notably in the second previous solution used by BDF2. On restart, the void fraction time derivative multiplies this error by a factor scaling as 1/dt, injecting a large spurious source in the continuity equation that led to an abnormally high first Newton residual and a loss of convergence. The ghost values of the interpolated void fraction vectors are now refreshed in `load_balance`, and, defensively, the deserialized void fraction vectors are re-ghosted in `read_checkpoint` to keep the invariant that these vectors are always ghosted outside of a solve. Note that checkpoints written by an affected run already contain the incorrect boundary values and must be regenerated. [#2069](https://github.com/chaos-polymtl/lethe/pull/2069)
