## [Master] - 2026/07/28

### Added

- MAJOR The multiphysic DEM capabilities of `lethe-particles` are now available within the CFD-DEM solvers, `lethe-fluid-particles` and `lethe-fluid-particles-matrix-free`. Setting `set solver type = dem_mp` in the `model parameters` subsection makes the particles carry a temperature and a specific heat, enables the conductive heat transfer between the particles, and integrates their temperature within the DEM sub-iterations. A new `DEM::CFDDEMMPProperties` index set was added for this purpose; it appends the thermal properties after the CFD-DEM ones so that it shares the exact layout of `DEM::CFDDEMProperties` for every property they have in common, an invariant which is enforced by a `static_assert`. The `PropertiesIndex` template parameter, which the DEM components already used, was propagated to `CFDDEMSolver`, `CFDDEMMatrixFree`, `FluidDynamicsVANS`, `FluidDynamicsVANSMatrixFree`, `ParticleProjector` and the particle-fluid VANS assemblers, and the applications now dispatch on the solver type. The particle-touching member functions of `NavierStokesScratchData` and `MFNavierStokesVANSPreconditionGMG::initialize` became member templates rather than class templates, so that the classes shared with the other Navier-Stokes solvers remain templated by the dimension only. Since the solver type only indicates that the DEM has its multiphysic features enabled, the `model parameters` subsection of a DEM packing simulation can be reused as-is in the CFD-DEM simulation which follows it, and `convert_particle_handler` now carries the temperature and the specific heat of the particles over when a multiphysic CFD-DEM simulation is restarted from a multiphysic DEM one. Note that the fluid and the particles do not exchange heat with one another, and that the particle-solid object heat transfer is not available since the CFD-DEM solvers do not support solid objects. The `3d-heat-transfer-in-aligned-particles` example was ported to `lethe-fluid-particles` in the new `unresolved-cfd-dem-multiphysics` example folder. [#2073](https://github.com/chaos-polymtl/lethe/pull/2073)

### Removed

- MINOR The `cfd_dem` value of the `solver type` parameter of the `model parameters` subsection was removed, leaving `dem` and `dem_mp`. This value was never read by any application: `lethe-particles` threw when it was used, and the CFD-DEM applications did not look at the solver type at all. The parameter now describes the physics carried by the particles rather than the application which is run, which is what allows the same value to be used for a DEM simulation and for the CFD-DEM simulation restarted from it. Input files which set `set solver type = cfd_dem` must use `dem` instead. [#2073](https://github.com/chaos-polymtl/lethe/pull/2073)
