## [Master] - 2026/10/12

### Changed

- MINOR The `lethe-parameter-check` executable now also parses the parameters after reading the parameter file, following the same sequence as the solvers (`declare()`, `parse_input()`, `parse()`). It consequently reports the errors and the warnings which are only raised when the parameters are parsed, such as the inconsistencies between the parameters of different subsections and the use of deprecated parameter values. The `check_parameter_files_in_examples.sh` script, which is used by the continuous integration to check the parameter files of the examples, monitors the output of `lethe-parameter-check` and now fails when a parameter file uses a deprecated parameter or a deprecated parameter value. The parameter file templates of the 2d-mms (`mms_quad/mms_2d_steady.prm` and `mms_simplex/mms_2d_steady.prm`), static-bubble-chns (`static-bubble-chns.prm`), bubble-detachment-shear-flow (`parametric_sweep/bubble-detachment-shear-flow.prm`) and 3d-granuheap (`granuheap_multicase.prm`) examples, which contain Jinja2 variables and cannot be parsed, are renamed with the `.tpl` extension.
